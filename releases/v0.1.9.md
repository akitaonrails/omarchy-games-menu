# v0.1.9

Covers for newly added games now actually finish downloading:

- `ogm refresh` is spawned detached (`setsid -f`) by the overlay. It used to
  be a plain child process, so closing the menu — picking a game, pressing
  Esc — killed it mid-flight. `ogm scan` is fast and had already listed the
  new games, which is why they appeared in the grid with no thumbnail while
  the SteamGridDB fetch that would have supplied one was cut short. The
  overlay falls back to an attached run if `setsid` is unavailable.
- `state.json` is now written after each cover instead of only at the end of
  the run, so a refresh that is interrupted keeps the covers it already
  fetched rather than discarding them and leaving the downloaded files
  orphaned. The overlay's live `state.json` watch means covers also appear in
  the grid as they land.
- New `cache/refresh.lock` single-instance guard: a detached refresh can
  outlive the overlay that started it, so a second launch could otherwise run
  a concurrent refresh and drop the first one's covers by last-writer-wins. A
  lock left behind by a killed process is detected and taken over.
- Refresh the full dependency tree (`tokio` 1.54, `hyper` 1.12, `rustls`
  0.23.46, `serde_json` 1.0.154, `sha2` 0.11.1, `aws-lc-sys` 0.46 and
  related). All direct dependencies are at their latest stable versions; no
  API changes were required.

Note: emulators and tools (Dolphin, PCSX2, RetroArch, …) still show the
generic icon by design — they ship without an `sgdb_query`, so no game cover
is looked up for them.
